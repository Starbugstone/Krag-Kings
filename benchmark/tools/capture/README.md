These capability checks are not game footage or performance measurements.

Windows Graphics Capture is now the default, following an actual successful Unity recording after GDI returned a frozen Direct3D surface. Build the explicit-window helper once with `Build-WindowCapture.ps1`. Launch one actual packaged engine demo in its showcase/wait mode under the shared heavy-task guard, then run the recorder from a separate PowerShell process, passing the real game process ID:

```powershell
.\benchmark\tools\capture\Capture-Demo.ps1 `
  -Engine Unreal -GameProcessId <actual-game-pid> `
  -RuntimeLog .\benchmark\unreal\evidence\runtime.log `
  -StartFlag .\benchmark\unreal\evidence\showcase-start.flag `
  -EngineAudio .\benchmark\unreal\evidence\showcase-engine-audio.wav `
  -OutputDirectory .\benchmark\unreal\evidence\showcase-review-01
```

For Unity, supply its corresponding runtime log, gate and game-only WAV paths with `-Engine Unity`. The recorder waits for the scene's `SHOWCASE_READY` marker, starts client-area capture of the explicit game HWND, then writes the gate. It records the 72-second timeline, waits for `SHOWCASE_COMPLETE` and the exported engine-only WAV, and muxes an H.264/AAC MP4. It does not capture desktop/system/microphone audio or change OBS configuration. The game remains running after capture. Existing final videos and WAV files are preserved; use a fresh output directory and archive task-owned audio before another recording.

The 30 fps recording rate is not a claim about engine frame rate. Run performance sampling separately. Capture aborts if its target loses foreground, minimizes, closes or changes client size. Before muxing, it compares known wide/action/portrait cues in a downsampled central viewport using pixel differences, checks the entire recording for five-second frozen plateaus, rejects any interval of at least one second with 98% near-black pixels, and rejects an empty/silent engine WAV using measured sample count, peak and RMS levels. It now also requires the game-only WAV duration to match the showcase within 0.5 seconds; it never pads or time-stretches an invalid recording. The explicit-window WGC backend is the verified path on this reference machine. Build it with `Build-WindowCapture.ps1`, then record in a fresh evidence directory; `-CaptureBackend WGC` may be supplied explicitly. `-CaptureBackend GDI` remains available for scoped diagnostic work, but its known frozen output is not usable demo evidence. The recorder never silently repeats a recording. The native helper uses only `CreateForWindow` with the validated HWND and owner PID, checks foreground/size throughout, and requires the intended borderless client dimensions to match the captured surface. It never calls monitor/desktop capture. Windows' capture border remains enabled. This path currently supports the demos' SDR BGRA8 output.

WGC sends real-time BGRA frames through a local named pipe to the same NVENC encoder. Its metadata records frame and repeated-frame counts, first scheduled output UTC and the first compositor-frame UTC. The constant 30 fps video repeats the latest image only when the compositor supplies no newer frame; this does not imply 30 unique game frames per second. A capture that falls more than half a second behind its real-time schedule fails with its partial media preserved. The recorder aligns engine audio to the first scheduled video-frame UTC, retains the same black/silent-media checks, and still requires visual and listening review. The native helper compiled successfully against MSVC 14.44/Windows SDK 10.0.26100 and has captured real running Unity and Unreal windows.
