It restores the authored point diameters after verifying topology and point order, commits `FHairDescription`, and rebuilds native data. All 12 curves/108 authored points survive; rebuilt triangle-strip data has 120 points because Unreal adds one terminal point per curve. Installed engine code and original ABCs stay unchanged. No renderer, character binding or performance proof exists yet.

The installed UE 5.8.3 distribution includes Groom (`HairStrands`) and Alembic Groom Importer (`AlembicHairImporter`). They are disabled by default. The benchmark already requests Compute Skin Cache shaders, DX12 and SM6; this does not prove actual strand rendering or skin-cache participation. The first probe enables the plugins only in a separate project under `benchmark/local/groom-probe`.

The actual Blender 5.2 fixture has three regional ABC files, each containing four curves and 36 points. Its native Blender roundtrip preserves positions/radii exactly. Blender 5.2 does not export the generic root-UV/color/group attributes, so separate assets and explicit regional material assignments will be used. Sidecar fields are evidence, not silently imported attributes.

`prepare.py --name <new-attempt>` freezes source/ABC hashes and creates guarded compile/import jobs. Add `--restore-point-widths` to enable the explicit sidecar adapter and the fresh-process reload job. The readback checks native point/strand counts, curve offsets, positions and per-point **diameters**; missing or constant fallback widths fail the exact-taper gate. This fixture deliberately retains ABC axes and scales metres to centimetres; it does not yet establish character-space conversion, binding, appearance or performance. The benchmark project, generated content, executable and shared assets are untouched. The [character checklist](character-pilot.md) records the next isolated import/binding gates.

The subsequent character pilot must use the exact current 79-bone rest mesh. It will start with Skinning binding, no physics simulation, no global/RBF interpolation and strands-only LODs. Rigid head attachment is insufficient for ear-tip/facial deformation. Regional hair material color must be explicit while native ABC color is absent. Binding must exclude old groom/clothing surfaces: installed `GroomBindingBuilder.cpp` shows `MatchingSection` controls transfer/RBF selection, while root projection needs the actual `TargetBindingAttribute` vertex mask. That mask must be proved in render-data buffers on a disposable matching mesh; a skin-only matching target is a fallback requiring equivalent pose proof.

The [first cleaned-character import](../../../unreal/evidence/groom-character-mask-v1/README.md) now proves that mask in the actual render buffer. Offline comparison of all79 origins passes, but the native retry is pending. The character sidecar/binding probes compile; their full binding, per-point color application and rendering have not executed.

Before drawing a conclusion on this RTX 2060 6 GB laptop, compare actual idle, walking, ear acting and close-up views; then measure native-1080p frame times and device VRAM separately from capture. Begin with the smallest reviewed regional groom, retain exact strand/point/width statistics, and use measured curve/point decimation and screen-size LOD. Simulation-off does not remove skin interpolation, voxel, shadow or lighting costs. No faster-than-cards, 60 FPS, full-density or final-art claim is made.
