# Prepared character strand check

This is a preparation checklist, not evidence of character import, binding, rendering or performance.

The actual Blender candidate is `benchmark/art/nib/groom-study/native-character-pilot-v1/source.json`: 26,000 curves, 234,000 points, five regions, canonical 79-bone Nib. The source preserves the current character and hides exactly the 22 old head/ear groom objects listed in `hiddenControlGroom`. Its measured native attachment and ABC roundtrip results do not establish Unreal attachment.

Nib's asset agent owns one common, isolated Natural FBX derived from the proven baked source `benchmark/art/nib/runtime-derivatives/coherent-neck-e1cdbd/Nib_Runtime_PBR.blend` (`fee71393f1a41355e309994118656494b320f1284f995259a5362fa82db0b4b1`). It removes those 22 objects before joining/export, retains remaining fuzz, and preserves PBR maps/UVs, bind, morphs and seven actions. No shared replacement is implied.

1. Verify the tiny exact-width adapter and fresh-process reload first. Preserve the failed stock-import result. For the larger character, freeze a separately justified positional tolerance from its measured ABC roundtrip; do not silently reuse or weaken the tiny fixture's gate.
2. Import the cleaned mesh into the disposable Groom project with a fresh skeleton and morph targets. Compare the full named bind hierarchy, scale and clip coverage. Establish the ABC-to-skeletal-mesh transform from actual positions/bind data; the fixture deliberately retained ABC axes and does not prove character alignment.
3. Verify the additive `KKGroomBindable` alpha-only color layer: RGB zero, alpha one only on the three actual skin objects used by the root regions, zero on all other exported objects. Enable FBX vertex-attribute import. Enable the named LOD vertex attribute for rendering, rebuild, and inspect the actual render buffer before binding. Preserve all existing source color layers and active selections.
4. Import each regional ABC and verify its point order/counts against pinned sidecars before restoring exact per-point diameters. Do not assert generic ABC root UV/color support: Blender 5.2 omits these attributes. Original sidecar surface UVs belong to the pre-bake source and must not be mistaken for the new PBR atlas coordinates.
5. Set `TargetBindingAttribute=KKGroomBindable`, then build a Skinning binding against the exact cleaned target. Reject a missing mask; Unreal otherwise falls back to allowing all vertices. `MatchingSection` controls transfer/RBF selection and is not a substitute for the root-projection mask. Assert all projected roots land on eligible target skin and inspect their distances.
6. Begin with native strands, no simulation and no global/RBF interpolation. Confirm actual Compute Skin Cache participation. Inspect neutral/front/profile, close-up, Idle, Run, Blink, Tongue and the authored ear-tip motion. Include a render without strands to isolate geometry/material faults. Shader colors and any restored sidecar attributes must be explicit.
7. Only after visible attachment/render checks, record a separate 1080p idle/moving/ear-expression workload with exact strand/point/LOD counts, frame times, GPU/device memory and run conditions. Tune density/LOD from measurements. Simulation-off still incurs skinning, interpolation, voxel, lighting and shadow costs.

Installed UE 5.8 source supporting this path: `FbxSkeletalMeshImport.cpp` accepts alpha-only vertex-color layers when `bImportVertexAttributes` is enabled; `FSkeletalMeshLODInfo::VertexAttributes` and `FSkeletalMeshVertexAttributeInfo::EnabledForRender` control the render buffer; `GroomBindingBuilder.cpp` reads that buffer through `TargetBindingAttribute` and admits a triangle when any of its three vertex values is positive. These are source findings, pending actual imported-mask and binding proof.
