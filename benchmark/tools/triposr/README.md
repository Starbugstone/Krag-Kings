# Isolated TripoSR reference pilot

This is a parent-authorized local experiment to assess whether image-derived geometry is useful as a sculpt/reference donor. It does not replace character art acceptance, the authored rig, or facial/limb topology. The network-only download and actual 60-package dependency resolution are complete with recorded hashes/licenses. The actual locked installation, CPU extension build and small sphere smoke now pass. One actual offline pilot has now run and failed geometry acceptance: it produced a thick rectangular plaque with shallow facial relief, not a complete head. See `benchmark/unreal/evidence/triposr-krag-bust-pilot-v1/`.

`download_only.py` consumes the pinned `network-download-plan.json`, streams public model/source/wheel files into `benchmark/local/triposr-downloads-v1` at at most 8 MiB/s, checks official model/wheel/config hashes, and records immutable-commit source-archive hashes. It does not extract or execute downloaded content, install packages, compile extensions, import Torch, touch the GPU, or change existing environments. This network-only stage may overlap art jobs with root's explicit authorization.

`resolve_environment.py` and `resolve-environment.job.json` have executed. They create a separate Windows Python3.10 venv/cache, install only pinned pip/setuptools/wheel/packaging bootstrap tools there, and obtain a dependency resolution report/hashed lock/license inventory. OmegaConf requires the pinned117KB pure-Python antlr4 4.9.3 source distribution; all other dependencies must resolve as wheels. Its original archive hash is checked, and metadata is evaluated with the pinned bootstrap backend under the guarded job. The resolver wrote its complete UTF-8 report, then the wrapper failed because its Windows default reader used cp1252. `finalize_resolution.py` consumed that exact report using UTF-8 without another resolution and passed its fresh completion gate. The original failure is preserved in `benchmark/unreal/evidence/triposr-resolved-environment/`. The reviewed inventory SHA-256 is `10a72e576e6613644ef9aeb30a6f67039387779aaf3695a08168d31466e598ca`. Bulk installation, native compilation and inference require their own granted resource boundary. Use the existing VS2022 toolchain for a separately pinned CPU-only `torchmcubes` extension rather than installing a global CUDA Toolkit.

The official TripoSR source/model are MIT. The chosen historical `torchmcubes` commit is MIT according to that commit's README/setup metadata; current master has different terms. PyTorch and each resolved transitive package must retain their actual license notices. Exact revisions and original license URLs are in the plan. Do not upload concept images; eventual input will be a preserved-sheet crop, evaluated locally. No global PATH, GPU driver, Blender, Unreal or existing Python environment changes are authorized by these scripts.

The first pilot input is frozen in `krag-bust-pilot.plan.json`: sheet01's upper-right Krag bust at(1400,0)–(1774,425), retaining original pixels and adding neutral512² padding only. `prepare_pilot_input.py` produced the checked exact crop/padding, and the first unrigged mesh is preserved as failed reference evidence. `install_environment.py` requires the SHA-256 of the reviewed resolution/license inventory, installs its hashed lock only inside the task venv, and builds the pinned original marching-cubes CPU sources with the existing VS2022 toolchain; its actual installation and CPU geometry smoke now pass. The CPU sphere has 480 vertices and 956 triangles, and all 60 installed runtime versions match the lock. Evidence is in `benchmark/unreal/evidence/triposr-installed-environment/`.

`run_reference_pilot.py` executed once with FP16-autocast forward, 256³ CPU-backed field extraction and 4096-position queries. It generated 213,184 triangles, but the actual color/clay views reject the plaque geometry. It checks actual free VRAM before model loading: FP32 GPU requires6.5GiB; FP16-autocast forward requires4GiB; otherwise the first run selects CPU. It never retries automatically after an OOM. The field extractor uses4096-position queries, stores the256³ density field as CPU float32, and runs the pinned CPU marching-cubes module. It does not allocate a full GPU grid. The actual result records precision, resolution, chunks, free/peak VRAM and execution times. The original Windows venv launcher hid the child Python worker from direct private-memory sampling; global headroom/commit checks and GPU telemetry remained active. The next Python job uses process-tree tracking. This first run was not repeated to repair telemetry. This is separate from the environment's passing small CPU-extension smoke, which does not load a model. `reference-mesh-review.job.json` produced eight actual neutral color/clay views of the saved GLB. Its raw Blender import axes leave the image-facing view sideways, but the slab and incomplete rear are unambiguous. One parent-authorized foreground-matted A/B is next; it has not run.

The authorized second input uses the installed rembg2.0.60 CPU session with the official U2Net asset (SHA-256 `8d10d2f3bb75ae3b6d527c77944fc5e7dcd94b29809d47a739a7a728a912b491`). Its network-only receipt and exact upstream Apache-2.0 license are preserved. The crop RGB and placement remain unchanged before alpha compositing, making the retained background the controlled difference. `triposr-prepare-matted-v2.job.json` must finish and its actual silhouette be inspected before `triposr-pilot-matted-v2.job.json` runs. Its eight planned upright color/clay views retain the original GLB and label the inferred rear noncanonical. These second-pass model stages remain unexecuted.
