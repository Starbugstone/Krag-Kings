Inference from those requirements: 32 GB system RAM makes a serialized CPU/chunked experiment plausible, but is not a measured peak-memory guarantee and does not substitute for GPU memory. Leave the engines/Blender closed during a future guarded pilot; the current heavy-job schedule and system headroom gates still apply. Do not extrapolate A100/H100 demonstrations to this laptop. No installation or trial is authorized by this research note alone.

The useful output would be a candidate external surface to compare with a single clean concept view under neutral turntable lighting. Occluded anatomy, separate eyes/mouth/tongue, garment layers and mechanical interfaces remain ambiguous from one image. Mesh extraction/remeshing does not provide animation-ready facial loops, the existing 79-bone rig, skin weights, corrective shapes, replaceable anatomy or exact identity.

If a later trial is authorized, preserve the generated object as an isolated donor/reference. First judge silhouette, facial landmarks, side/back inference and color against the concepts. Only a visibly useful result merits retopology/sculpt correction and transfer onto the existing authored skeleton/action pipeline, followed by full deformation and engine review. Stop a poor reference trial rather than incorporating attractive but incorrect anatomy. No model guarantees concept-exact results.

## TripoSR dependency and download inspection

Metadata-only queries are saved in [download-metadata.json](download-metadata.json). The actual official checkpoint is **1,677,246,742 bytes**, SHA-256 `429e2c6b22a0923967459de24d67f05962b235f79cde6b032aa7ed2ffcd970ee`; its config is 987 bytes. Current inspected repository commit is `107cefdc244c39106fa830359024f6a2f1c78871`. The tokenizer fetches only the 454-byte DINO configuration: its weights are included in the TripoSR checkpoint, so an extra full DINO weight download is not required by this code. [Official model files](https://huggingface.co/stabilityai/TripoSR/tree/main), [tokenizer implementation](https://github.com/VAST-AI-Research/TripoSR/blob/main/tsr/models/tokenizers/image.py).

An illustrative official Windows Python3.11/CUDA12.1 PyTorch2.5.1 wheel reports **2,449,385,544 bytes** through HEAD metadata; it was not downloaded or selected for installation. Checkpoint plus that one compressed wheel already total about4.13GB, before other dependencies, unpacking and caches. A provisional15–20GB workspace allowance is an estimate, not a resolved install size. The D: volume currently has about533GiB free. [Official PyTorch version matrix](https://pytorch.org/get-started/previous-versions/).

The official requirement file mixes exact older versions with unpinned packages and an unpinned Git-native `torchmcubes` dependency. Current upstream `torchmcubes` uses C++20/CMake and supports a CPU extraction build without installing the CUDA Toolkit; its own license is MPL2.0. PyTorch GPU inference and CPU mesh extraction can therefore be evaluated independently, with actual compatibility still untested. The texture bake also requires an OpenGL context; an initial vertex-color mesh avoids exercising that bake path. [Requirements](https://github.com/VAST-AI-Research/TripoSR/blob/main/requirements.txt), [torchmcubes build requirements](https://github.com/tatsy/torchmcubes), [CPU extraction fallback](https://github.com/VAST-AI-Research/TripoSR/blob/main/tsr/models/isosurface.py), [texture baker](https://github.com/VAST-AI-Research/TripoSR/blob/main/tsr/bake_texture.py).

Isolation proposal: a dedicated interpreter/environment and all package/model/temp caches under `benchmark/local`, using only child-process environment variables. Do not install into Blender, Unreal, system Python, or the existing WSL Python3.12.3; do not change global PATH, GPU drivers or existing tooling. Resolve/pin the complete dependency graph before a scheduled bounded installation, then measure the actual import/extension compatibility and memory. The exact dependency resolution and an installed environment do not yet exist at this checkpoint.
