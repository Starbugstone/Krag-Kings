The packaged Unity 6000.4.4f1 demo passed the native mouse/keyboard sequence on 6 October 2026 at 03:49 CEST. Build GUID `c4767943faf24b91b8fbc5157f46b339`; source/build identifiers are in `result.json`. The F12 image was inspected and shows the actual final scene, with the Nib grip replacement selected and Krag crusher visible. **Character likeness remains unaccepted. This is interaction evidence, not a framerate measurement or finished art.**

The check covers simultaneous Krag melee and Nib shooting after selecting each separately, orbit/zoom and pan while actions play, each species' selection and portrait/facial controls, melee/shoot/hit keys, variant changes, right-click running and Shift/right-click walking. Actual travel was 2.71m for Krag and 2.80m for Nib. The earlier automated all-variant morph/action/dune checks are preserved locally under `20261006-032403`, build `2f16ff5e93f64b209996a6f4f7318142`, with the same content fingerprint; the native check uses the later keyboard/camera build and does not mislabel that earlier report as its own run.

Two product fixes were necessary: letter shortcuts now use the current keyboard layout (the host's French keyboard labels Unity's physical `aKey` as Q), and wheel zoom uses the pinned Input System's normalized one-unit notch. The earlier 0.005 multiplier made zoom impractically slow; the new proposed sensitivity is 0.6m per notch.

The Windows verifier also needed correction. It now sends scan-code input, explicitly preserves the extended navigation keys, performs a short relative mouse-drag sequence, reads atomic probe snapshots with delete-sharing, and zooms out before clicking the chosen sand destination so the bottom controls do not cover it. On this host both ANSI and Unicode `MapVirtualKeyEx` with map type 4 returned 0x0047/0x004D for Home/Right without E0; actual Unity diagnostics identified the injected keys as numpad7/numpad6. Explicit navigation E0 flags produced `home / Origine` and `rightArrow / Droite`, followed by the actual full pass. No game binding was changed to accept mistaken keypad events.

Failed intermediate reports remain in the local `unity-interactive/20261006-034131` directory; the initial zero-scan-code overlap failure is in `20261006-032650`. They are superseded only for the specific defects verified here. The injector follows Microsoft's [scan-code input structure](https://learn.microsoft.com/en-us/windows/win32/api/winuser/ns-winuser-keybdinput) and [layout mapping API](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-mapvirtualkeyexw).
